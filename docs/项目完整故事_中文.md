# 这个项目到底做了什么：从呼吸音 schema 到临床 metadata alignment audit

> 本文不是逐句硬翻译，而是把整个仓库的英文材料整理成一条能顺着读懂的中文故事。仓库里保留了不少“当时成立、后来被对照推翻”的记录；本文以目前最严格、最可辩护的口径为准。2026 年 8 月新增的 UKCOVID Route-A audit 已在本文开头补入；后文保留 ICBHI/schema 探索的完整历史。

## 一句话结论

**项目分成了两条相连但不同的故事。第一条在 ICBHI 上发现：结构化 schema 和自然语言都没有改善呼吸音的全局分类表示，直接使用 AST 前六层更好。第二条在 UKCOVID 上发现：正确的 audio--metadata pairing 确实学会了患者 profile correspondence，但这种对应没有稳定变成跨人群、跨 backbone、跨 readout 的疾病收益。CODA TB 的 secondary external sensitivity 进一步显示：在另一种疾病、七国临床数据与三个 backbone 中，Correct pairing 同样增强患者对应与人口学信息，但 matched TB transfer 不确定且方向不一致。共同教训是：alignment 成功不能只由训练损失、检索或源域分数定义，必须检查它学到的通道以及能否迁移。**

## 最新篇章：UKCOVID Pairing-Controlled Transfer Audit

后续工作把问题从“schema 是否优于自然语言”推进到一个更一般的评价漏洞：clinical metadata
同时包含疾病、患者、症状和 cohort 信息，模型把音频与 metadata 对齐成功，不等于学到了可迁移
的疾病声学证据。

为此训练三种只改变配对的 arm：

- `correct`：正确的逐患者 metadata；
- `within-label`：只在相同 COVID 标签内打乱，保留标签／人群共现、破坏患者对应；
- `global`：全局打乱，同时破坏患者对应和标签共现。

Route-A 最终结果是：

1. AST-6L 与 OPERA-CT 的 unique-profile retrieval 都满足 `correct > within > global`；事后
   HeAR 第三骨干也得到 Correct−Within +0.0071 [0.0048, 0.0097]，所以 alignment 的确学到了
   患者对应；
2. matched probe 中，correct 相对 within 明显保留性别（AST +0.191 AUROC、OPERA +0.112），
   但 COVID 增量分别为 +0.006 和 −0.002，区间都覆盖 0；事后 HeAR 的性别增量为 +0.086，
   COVID 增量仅 +0.003，区间同样覆盖 0；
3. raw audio、metadata fusion、线性读出和固定 MLP 均未得到稳定跨 backbone 的疾病迁移收益；
4. source-calibrated NLL 变差而 target recalibration 后差距约为 0，这与目标人群中的概率尺度
   失配一致，但不能单独识别机制；疾病排序并没有因此出现；
5. 新增“同标签且同性别换人”的 `W_{y,s}` 对照后，AST、OPERA、HeAR 的 Correct−`W_{y,s}`
   性别差异都大幅削弱到区间覆盖 0，而 `W_{y,s}`−Within 都明确为正。这说明原来最强的 sex
   probe 对配对规则是否保留记录性别一致性高度敏感，但不是因果分解或等效性证明；
6. 控制性别后，profile retrieval 仍有很小的 residual correspondence（AST 边界正、OPERA
   跨零、HeAR 明确为正），但 matched COVID 仍没有跨 backbone 收益。即使用 matched-long
   标签训练 target-assisted readout，再到独立 matched 测试，也没有建立跨 backbone 一致的
   Correct−Within 或 Correct−Raw 优势；OPERA 区间仍允许有意义的正效应，因此不能声称已经
   排除 readout training 的影响；
7. synthetic 只通过 correspondence gate，未通过一般机制门；Coswara 的预注册贪心数据门
   NO-GO，但模型盲的全局约束 secondary cohort 通过并完成三骨干 post-hoc 压力测试：三者
   retrieval 点估计和性别 probe 均 `Correct > Within`（AST retrieval 区间跨 0），primary
   matched `C-W_{y,s}` COVID 增量均不显著。CODA TB 的
   原始 split-first 数据门也 NO-GO，但在没有读取模型输出时另行冻结的
   match-first v2 成功构造出100对平衡 target（max SMD 0.0819）并完成正式模型实验。
   AST／OPERA／HeAR 的 profile retrieval 都显著 `Correct > Within`；性别信息在三个 backbone
   中稳定增强，年龄信息仅在 AST 明确；matched TB `C-W_{y,s}` 在 AST 为 +0.0476
   AUROC，在 OPERA 为 −0.0077、HeAR 为 −0.0102，CI 均跨 0，
   因此是 correspondence 成立但 transfer inconclusive。Cambridge 已确认是官方Task-2音频
   子集上的custom strict-COVID cough endpoint，不是UKCOVID或症状任务；身份审计修正了旧
   gate合并18个Web submission的问题。新队列为989人和100个匹配对，并已完成AST、OPERA与
   HeAR：三个 backbone 的 profile retrieval 均显著 Correct>Within，三个 backbone 的性别
   probe 都显著增强，但 primary matched `C-W_{y,s}` COVID 均未显著为正。

最准确的一句话是：

> **模型学会了“这段声音对应什么样的患者”，但没有稳定学到能跨人群使用的疾病证据。**

`W_{y,s}` 使用与原三臂相同的 20,714 名 UKCOVID 训练参与者，禁止自配对、singleton fallback
和跨层 fallback。它保证换到不同参与者，但 schema 仍可能相同：其 exact-schema collision 为
6.35%--6.61%，原 Within 为 3.03%--3.33%。因此结果图只能写“different participant”，不能写
“different profile”。

条件化 retrieval 也支持同一边界：把候选限制为同性别后，原 C−W 在 AST／OPERA 上区间跨零，
HeAR 仍为正；限制为同标签且同性别后，HeAR 仍为正、AST 位于边界、OPERA 跨零。这说明粗粒度
性别匹配可以衰减 retrieval，但不能解释所有 backbone 的 correspondence。

完整数字和边界见 `ICASSP_EXECUTION_STATUS_ZH.md`；最终可审计 JSON 见
`results/route_a_final/` 与 `results/pairing_followup/`。E1--E3 完整诊断见
`PAIRING_AUDIT_E1_E2_E3_OUTCOME_ZH.md`。下一阶段的 disease-invariant positive-pair 设计已经
写下，但尚未运行。

## 一、最初为什么想做 schema

音频—文本对比学习试图把配对的声音和文字放到相近的向量位置，把不配对的推远，从而学到声音和语言之间的对应。

但呼吸音里的常见文本往往写年龄、性别、症状和诊断，这些描述患者，不是声音本身。真实使用时可能只有录音，没有完整问卷。因此项目提出：

> 与其把呼吸音对齐到自由文本或患者元数据，不如对齐到结构化声学 schema。Schema 可以明确表达 wheeze、crackle、音高、强度、频带、置信度和证据来源，也许能向频谱提供更细的映射。

这就是整个项目要检验的核心主张。

## 二、数据与基本陷阱

主数据是 ICBHI 2017，主要目标是：

- **Wheeze，哮鸣音**：持续较长，比较适合 AST 大约 100 ms 的时间步长。
- **Crackle，爆裂音**：可能只有 5–20 ms，而且容易被设备、听诊位置和周期时长混淆。

早期文档曾把“patient_id 小于等于 160”当成官方划分，后来发现是上游注释错误。它和真实官方划分只在 53.5% 的录音上一致。仓库后来重建了官方划分，并确认主要结论不依赖某一个划分。

所有关键评估都按患者隔离。否则同一患者的设备、环境和生理特征可能同时进入训练和测试，模型只是在认人或认设备。

KAUH 用来检查 AST 相对呼吸音专用编码器的优势能否跨数据复现。Coswara 的原始模型盲贪心
数据门因 strict matching common support 不足而停止；透明版本化的全局约束 secondary cohort
随后完成三骨干 post-hoc 压力测试，并再次观察到 correspondence 与 transfer 分离。CODA TB v1 也停止，但透明版本化的 match-first
v2 已完成正式 secondary external sensitivity：它复现了 correspondence 明确增加而
matched disease transfer 不稳定的核心形状。COUGHVID用于 teacher feasibility，而不是当前核心
疾病迁移结论的证据。Cambridge已完成数据集身份核对、修正版真实WAV数据门与三backbone
正式外部敏感性实验；结果重复了patient correspondence与matched disease transfer分离的主形状。

## 三、文本里到底有什么

在训练对比学习之前，项目先统计了不同文本条件的信息量。

| 文本条件 | 6,898 个周期中的不同文本数 | 平均词数 |
|---|---:|---:|
| dataset：听诊位置和设备 | 27 | 10.0 |
| model：模型粗粒度判断 | 193 | 24.0 |
| signal：信号特征 | 1,786 | 27.7 |
| all：完整 schema | 3,552 | 39.3 |
| T1：Qwen2-Audio 自由叙述 | 2,448 | 54.1 |

当时曾猜测：文本状态越多，对比学习越容易获得有效负样本。后面的实验否定了这一点，性能并不按 27、193、1,786、3,552 的顺序改善。

这里还发现：

1. **Crackle 的设备和位置混淆很强。** 只看设备和听诊位置，AUROC 已经达到 0.637，与加入声学线索后几乎一样。
2. **Wheeze 更干净。** 只看设备和位置时 AUROC 是 0.390，加入声学线索后才上升。

所以后续优先研究 wheeze；任何 crackle 数字都必须和设备、位置、时长基线一起解释。

## 四、全局音频—文本对齐的结果

最初模型是：

    音频 → 冻结音频编码器 → 可训练投影头
    文本 → 冻结文本编码器 → 文本向量
                           ↓
                       对比损失

评估不能只看训练 loss 或检索，而要看对齐后的音频表示能否提高下游 AUROC，并且必须与“不对齐、直接探测原始音频特征”比较。

AST 加 Bio_ClinicalBERT 的一组代表结果：

| 条件 | Wheeze AUROC | Crackle AUROC |
|---|---:|---:|
| RAW AST，不对齐 | **0.857** | **0.689** |
| Qwen2-Audio 自由叙述 | 0.629 | 0.606 |
| 完整 schema | 0.613 | 0.615 |
| model 字段 | 0.579 | 0.599 |
| signal 字段 | 0.521 | 0.608 |
| dataset 字段 | 0.455 | 0.617 |

真正重要的不是“schema 比叙述差一点”，而是：**所有对齐条件都比不对齐差。**

### 为什么早期 model 文本看起来最好

在 OPERA-CT 作为音频编码器时，model 文本一度最好。但 model 文本本来就是由 OPERA-CT 的预测产生的。投影头只需恢复同一模型家族的输出，不必学习临床语义。

项目在换成没有这种血缘关系的 AST 前，预先预测 model 条件会掉下去；实验确实如此。这说明早期优势来自循环依赖，不是临床 grounding。

### 放开音频编码器训练也没超过 raw AST

可训练编码器相对只训练投影头确实增加约 0.10–0.20 AUROC，但代表性 wheeze 最好结果约 0.771，仍低于 raw AST 约 0.796。

所以冻结 tower 只是部分瓶颈，不是完整解释。

### 更多负样本反而更差

扩大 negative queue 后，结果在约 1,024 附近饱和，继续增加反而更差。许多只差一档的 schema 被当成完全负样本，促成了后来的 multi-positive 实验，但后者也没有稳定改善。

### 真正 zero-shot 没有救活方法

早期的类别文本 prototype 使用训练标签，不是真零样本。改成不使用标签的手写 prompt 后：

- 真 zero-shot 最高约 0.614。
- Wheeze 加 T1 可低到 0.425。
- 用 schema 语气或叙述语气写 prompt，会翻转两个条件的排名。

因此所谓 schema 更容易 prompt，实际只是 prompt 与训练文本风格是否匹配。

### Qwen2-Audio 叙述几乎没有标签信息

| 目标 | 真实存在时声称存在 | 真实不存在时声称存在 | 文本 AUROC |
|---|---:|---:|---:|
| Wheeze | 0.344 | 0.327 | 0.509 |
| Crackle | 0.306 | 0.290 | 0.508 |

它大约三分之一时间会说有 wheeze，不管标签里到底有没有。T1 在某些 probe 中仍较好，因此其优势更像“每个样本都有不同训练目标”的文本形自监督，而不是准确临床内容。

## 五、项目最稳定的正结果：AST

| 编码器 | 参数量 | ICBHI Wheeze | ICBHI Crackle |
|---|---:|---:|---:|
| **AST 前 6 层** | **43.7M** | **0.807** | **0.750** |
| 完整 AST | 86.2M | 0.796 | 0.729 |
| OPERA-CT | 32.4M | 0.606 | 0.621 |
| OPERA-CE | 5.0M | 0.531 | 0.594 |
| StethoLM 音频编码器 | 5.0M | 0.512 | 0.562 |

这个结果通过了标签打乱、特征配对打乱、患者隔离和时长基线检查。AST 减到前六层没有变差，多数任务反而更好；在 KAUH 患者级任务上四项赢了三项，COPD 是反例。

最实用建议是：**继续研究呼吸音表征时，优先从 AST 前六层开始，不要默认领域专用编码器一定更好。**

这不代表 OPERA 或其他已测编码器在所有任务都差。仓库只测了有限编码器和语料；CLAP、
AudioMAE 等其他模型家族仍未比较。

## 六、第二阶段：把分类与 grounding 分开

第一阶段一度因为全局平均池化对分类最好，就断言局部对齐也没有空间。后来确认这是过度外推：

- 池化诊断问哪种读出提高周期级分类 AUROC。
- Grounding 问 schema 字段能否指向频谱中的证据。

分类不变好不能否定解释性定位。因此第二阶段重新打开更窄的问题：结构化字段能否学习 field-to-patch 对应？

AST 的真实 patch 网格是：

- 12 个频率位置乘 101 个时间位置，共 1,212 patches。
- 加两个特殊 token，共 1,214 tokens。
- 时间 stride 约 100 ms，感受野约 160 ms。
- ICBHI 周期平均约 2.7 s，AST 填充到 10.24 s，约 73%–74% 时间 patch 是 padding。

因此 occupancy mask 是必需品。Wheeze 可跨多个 patch；crackle 只能做粗粒度 Hit±1，不能宣称毫秒级 IoU。

## 七、第二阶段的三个全局实验

### 假设 8：false negatives 是主要原因

Single-positive、exact multi-positive 和 soft multi-positive 在 wheeze 与 crackle 上都没有稳定改善。

可辩护结论：**false negative 不是全局失败的主要解释。**

早期代码出现过对角线重复加权、反向目标归一化和诊断 batch 不具代表性等问题，所以应说“未发现可重复改善”，不要说“已彻底排除所有影响”。

### 假设 9：同样内容的不同写法有用吗

匹配信息内容、只改变模板或序列化形式后，差异很小、区间跨零，处理 duration 后方向还会翻转。

结论：**未找到可复现的序列化格式效应。**

### 假设 10：typed schema encoder 有用吗

第一版在 wheeze 上一度改善，但 crackle 方向反转，打乱 schema 后大部分增益仍在；原 no-field 对照也没有真正删除字段身份。

审计结果：

| 条件 | Wheeze AUROC |
|---|---:|
| RAW AST，不对齐 | 0.796 |
| Constant schema | 0.750 ± 0.018 |
| Intact typed schema | 0.705 ± 0.011 |
| No-field | 0.699 ± 0.030 |
| Record-shuffled | 0.650 ± 0.025 |

Intact 减 shuffled、constant 和 no-field 的三个 95% 区间都跨零。因此严格说法是：

> 粗粒度 typed schema 没有显示可靠的全局表示改善；数字方向像是对齐在伤害原始 AST，但 intact、constant 和 shuffled 的机制差异仍不确定。

而且它并未真正实现事件 onset/end、实际 Hz、谐波性、周期性、phase、局部 confidence 和 evidence mask 等细粒度 Schema v2。

## 八、为什么先做合成 grounding

ICBHI 只有周期级 wheeze/crackle 标志，没有事件时间戳和频率框。

在映射机制尚未证明时，直接标 100–200 条真实音频很可能浪费成本。因此先在 normal cycle 上注入已知时间和频率的合成事件，用生成参数自动产生标签。

合成实验最多回答：

> Query 与 patch 的映射机制在控制条件下能不能跑通？

它不能回答：

> 模型能否在真实患者呼吸音里做临床可用的 wheeze grounding？

## 九、三次 grounding 设计问题为什么必须撤回

### 版本 0：单注入，query 可以被忽略

每段音频只放一个明显事件。即使打乱 query，模型也能直接找最显眼的音。

| 条件 | Hit±1 |
|---|---:|
| Typed intact | 0.965 |
| Shuffled query | 0.977 |

这不是 grounding 负结果，而是任务无法测量 grounding。

### 版本 1：双注入，但 query 直接包含答案

每段音频放两个事件后，一度得到：

- Intact Hit±1 为 0.935。
- Shuffled coordinates 为 0.494。
- Query 换成干扰事件坐标后，90.1% 的 peak 跟到干扰事件。

但 query 包含事件中心时间、duration 和 f0，而目标 patch 正是这些值的确定性函数。

| 条件 | Hit±1 | 频率准确率 | 2D |
|---|---:|---:|---:|
| Coordinate-only，无音频 | **1.000** | **1.000** | **1.000** |
| 学到的模型 | 0.935 | 0.894 | 0.582 |

所以任务测的是坐标算术，不是 grounding，这个正结果必须撤回。

当时的 energy-tonality 基线也实现错了：它计算 AST embedding 的 L2 模长，没有真正计算频谱能量，因此低分不能证明任务很难。

### 版本 2：query 只剩一个 bit，但 target mask 泄漏类别

新设计让同一音频产生两个 character query，坐标不再进入 query。

但只对 poly 比例做了几何均值归一化；mono 的比例仍使频谱中心高约 41%，mask 范围和 patch 数也不同。

完全不看音频、只看 crop 和 mask 几何的分类器就能达到 AUROC 0.982。所谓 feasibility 1.000 主要是在读裁剪框位置，不是声学内容，因此也必须撤回。

三次问题形成一条规则：

> 不仅 query 不能包含答案；任何与类别绑定的位置、mask 范围、patch 数、padding 或合成参数都可能成为答案。

## 十、v2.1：第一个几何上较干净的机制探针

### 它已经不再是临床 mono/poly wheeze

为了从构造上锁死几何差异，v2.1 让两类事件都有三个同时分音，两端固定，只移动中间分音：

    Harmonic：   fc × {1, 2.000, 4}
    Inharmonic： fc × {1, 1.550, 4}
    或            fc × {1, 2.581, 4}

上下两种 inharmonic 偏移对称平衡，使平均 log-frequency 中心几乎一致。Target mask 使用两端之间的完整频带，不使用实际占用行的并集。

代价是：**这不再是临床 mono/poly wheeze 代理。** Mono/poly 的关键是分音数量不同，而 v2.1 为排除几何差异，把分音数量对齐了。它只测试合成的谐波与非谐波结构。

### 可行性门

只使用官方 train，再按患者拆内部 train/dev：

| 探针 | AUROC | 95% CI |
|---|---:|---:|
| 只看几何，不看音频 | 0.477 | [0.412, 0.538] |
| 已知位置的 harmonic/inharmonic crop | 0.999 | [0.997, 1.000] |
| 事件与背景 | 1.000 | [1.000, 1.000] |

这说明几何已无法预测 character，AST 区域特征确实含有足够区分两种合成形态的信息。

但 0.999 是在真实位置已知后对固定 crop 分类，只证明可解码，不证明能从全图自动定位。

### 简单 query-to-patch 头的开发集结果

每个 clip 有 harmonic 和 inharmonic 两个事件。同一音频产生两个 query：

    query = harmonic   → 指向 harmonic 区域
    query = inharmonic → 指向 inharmonic 区域

模型对每个 AST patch 做线性投影，再与二元 query embedding 点积。它不联合读取整个 crop，每个 patch 独立得分。

| 条件 | 两候选区域 2AFC | 解释 |
|---|---:|---|
| 已知位置的 crop 分类器 | 1.000 [1.000, 1.000] | 给出真实 crop 后形态完全可分 |
| 简单 per-patch query 头 | **0.569 [0.538, 0.605]** | 高于 0.5，但很弱 |
| Query-conditioned DSP | 0.549 [0.481, 0.607] | 区间覆盖随机 |
| Query only | 0.500 | 随机 |
| Constant query | 0.500 | 随机 |
| Position only | 0.510 | 随机 |
| Shuffled query | 0.493 | 随机 |
| Shuffled audio | 0.521 | 随机 |
| Zeroed audio | 0.507 | 随机 |
| Permuted target | 0.503 | 随机 |

全局 argmax 落入目标区域的比例是 0.546；constant query 也可达到 0.442。这说明找到某个合成事件不难，真正弱的是根据 query 在两个事件里选对一个。

三个优化器随机种子的 intact 2AFC 分别为 0.615、0.582 和 0.511，说明平均效应对训练随机性较敏感。逐样本、逐 seed 的二元 2AFC win indicators 已保存在结果文件中。

在先对三个 seed 求平均、再按患者聚类 bootstrap 的分析中，intact 相对 chance 的差值为 +0.069，95% CI 为 [+0.038, +0.105]；相对 query-shuffled、query-constant、target-permuted、position-only 和 audio-shuffled 的配对区间也排除零。相对 audio-zeroed 与 DSP 的区间仍覆盖零。

这套区间主要表达患者采样不确定性，没有完整纳入 optimizer seed 的随机性。因此“弱效应高于随机”有支持，但对某个具体 ablation 的强因果解释仍应保守。

### 这个结果严格来说意味着什么

英文 README 把 0.569 对照 0.60 门槛写成 grounding rejected 或 sealed。更严格的解释应分三层：

1. **不是完全没有信号。** 0.569 的患者级区间高于 0.5，说明简单头学到了一点 query-conditioned region preference。
2. **信号弱到不值得继续投入。** 它没有达到选定开发门槛，不足以支持打开官方 test 或开始真实 wheeze 标注。
3. **只限制一种读出头和一种合成任务。** 已知位置的 5×3 crop 分类器达到 1.000，说明区域联合信息存在。当前 per-patch 头不能证明 region-aware head 或 cross-attention 一定失败。

还要注意：

- Query flip 等于 1 减 intact，在双 query 对称 2AFC 中基本是代数互补，不是独立证据。
- Crop classifier 事先知道两个候选区域在哪里。它是 oracle-location crop classifier，不是全图定位 oracle。
- Grounding 的 0.60 门槛没有在结果提交前单独版本化。没有其他带时间戳记录时，最好称为固定开发门槛，而不是严格仓库级预注册。
- Intact 相对各 control 的患者级配对差值已经报告；但当前做法先平均 seed 再 bootstrap 患者，不能替代逐 seed 数字或患者×seed 两层不确定性分析。
- 当前 query-shuffled 同时打乱 train 和 dev，更像推理时 scramble；它不能单独支持“训练对应关系”的因果主张。若不再运行新对照，应按实际操作命名。
- 当前 NPZ 文件保存的是逐样本二元 win indicators 和标识信息，不是完整 score grid、region margin 或 argmax 坐标，因此应准确称为 per-example, per-seed 2AFC win indicators。

最终可辩护口径是：

> AST patch 中包含这个合成属性；简单独立 per-patch query 头只能提取微弱、高于随机的条件定位信号，但不足以支持进入留出测试或真实标注。可以封存这个读出头，不应外推为所有 grounding 架构都被否定。

## 十二、最重要的撤回记录

| 曾经的说法 | 后来发现 |
|---|---|
| Structured schema 优于自由叙述 | 所有对齐都低于 raw features。 |
| 对齐带来 zero-shot 能力 | Prototype 使用训练标签；真 zero-shot 更差。 |
| Schema 更容易 prompt | 换一种 prompt 语气就翻转排名。 |
| 池化诊断关闭所有局部对齐 | 它只回答分类 AUROC，没有回答 grounding。 |
| patient_id 阈值是官方划分 | 上游注释错误。 |
| Typed schema 第一次通过标准 | Crackle 反转，shuffle 保留大部分增益，实现和统计还有问题。 |
| Grounding 0.935 是首个正结果 | Query 含目标坐标，无音频基线达到 1.000。 |
| v2 feasibility 1.000 证明 AST 听出类别 | Target-mask 几何单独达到 0.982。 |

这些撤回不是项目没有价值。它们说明：**每次错误结论，都是被一个比继续大规模训练更便宜的对照推翻的。**

## 十三、整个项目应该怎样讲

不要讲成“我们试了十一个小点，它们全失败”。更清楚的故事只有三幕。

### 第一幕：Schema 比自然文本更好吗

没有。无论使用自由叙述、粗粒度 schema、typed schema、更多负样本、multi-positive、冻结编码器或可训练编码器，都没有超过 raw AST 的全局表示。

这里最强的结果不是哪个文本条件最好，而是：**不做对齐最好。**

### 第二幕：什么音频编码器值得用

通用 AudioSet AST 前六层，在相同数据、划分和 probe 下明显超过已测呼吸音专用编码器。

这是最可靠、最易复现、最有工程价值的正结果。

### 第三幕：Schema 至少能帮助局部定位吗

早期两个看似正面的合成结果分别由坐标和几何泄漏造成。V2.1 把明显几何泄漏压到随机水平，并确认 AST 区域里有声学形态信息。

但简单 per-patch query 头只学到 0.569 的微弱条件选择信号，虽高于随机，却不足以支持继续投入官方测试和人工标注。

所以封存的是**当前简单读出头的开发路线**，不是“所有 schema grounding 都不可能”的普遍定理。

---

## 十四、现在应该做什么

1. **不打开官方 grounding test。** 开发集没有达到继续投入门槛。
2. **不开始真实 wheeze 标注。** 合成机制还不够强。
3. **不再更换 loss、文本模板或负样本数量。** 这些路线已有充分负证据。
4. **逐样本 win indicators 和患者级配对差值已经保存。** 最后只需在文字中同时报告逐 seed 结果，说明现有区间主要覆盖患者采样不确定性，并修正 query-shuffle 与 prediction 文件的命名边界。
5. **收窄英文 README。** 应写“开发集上存在微弱但高于随机的信号，未进入留出测试”，不要写成“所有 grounding 已被普遍否定”。

如果未来研究 region-aware scorer、cross-attention 或真实事件标注，应把它当作全新项目和新假设，而不是为了挽救当前结果不断移动门槛。

## 一个在会议上可以直接讲的版本

我们原来想验证，结构化声学 schema 是否比自由文本更适合呼吸音对比学习。但在两种数据划分、两类音频 tower、两类文本 tower、多种文本条件、两个下游目标和多个训练变体中，没有一个全局对齐结果超过直接使用 raw AST 特征。与此同时，通用 AudioSet AST 前六层稳定超过已测的呼吸音专用编码器，这是项目最可靠的正结果。

我们后来把问题缩小为 schema 是否至少支持频谱局部定位。前两个合成正结果分别被坐标泄漏和 target-mask 几何泄漏否定。最终 v2.1 将明显几何泄漏压到随机水平，AST 在已知位置的 crop 中几乎完美编码了声学区别，但简单 per-patch query 头只得到 0.569 的微弱条件区域选择。这个信号高于随机，却不足以支持进入官方测试或真实标注。

因此，项目的贡献是一组有控制、有诊断、保留撤回记录的系统负结果，加上一个独立而稳定的正发现：AST 前六层是当前已测条件下更好的呼吸音基础表示。

## 常用英文术语的白话解释

| 英文术语 | 中文理解 |
|---|---|
| Schema | 结构化字段集合，例如声音类型、音高、强度、置信度和来源 |
| Contrastive learning | 让配对样本靠近、不配对样本远离 |
| Alignment | 将音频与文本或结构映射到可比较的表示空间 |
| Tower | 音频编码器或文本编码器这样的一条模型分支 |
| Frozen tower | 参数不更新的编码器 |
| Projection head | 把编码器输出变换到对齐空间的小网络 |
| InfoNCE | 常用的对比学习损失 |
| Raw feature probe | 不做对齐，直接在原始音频特征上训练简单分类器 |
| Linear probe | 用线性分类器检查表示里有多少可读信息 |
| Zero-shot | 不用目标任务标签直接完成分类 |
| Grounding | 不只说有什么声音，还指出频谱中的证据位置 |
| Patch | AST 将频谱图分块后的局部单元 |
| Occupancy mask | 标记真实音频 patch 和 padding patch |
| Shortcut | 模型利用数据泄漏规律得高分，而没有做目标任务 |
| Ablation | 删除、打乱或替换某部分，观察结果变化 |
| Control | 用来排除替代解释的对照条件 |
| Multi-positive | 一个样本允许多个相似正样本的对比目标 |
| Patient bootstrap | 以患者为群组重采样估计置信区间 |
| 2AFC | 在两个候选区域中选出 query 指定的一个 |
| Oracle | 获得真实位置等额外信息的可行性上界，不是实际模型 |
| Pre-registration | 看结果前带时间记录地固定假设、指标和成功标准 |

## 最后的准确口径

这个项目不是“schema 完全没有价值”的普遍证明，也不是“所有对比学习都无效”的结论。

它支持的是：

1. 在已测数据、编码器、文本和训练设置下，全局音频—文本/schema 对齐没有超过 raw AST。
2. 文本分辨率、负样本数量、multi-positive、序列化格式和粗粒度 typed encoder 都没有提供稳定解法。
3. AST 前六层是仓库里最稳定的正面发现。
4. 早期 grounding 正结果来自坐标或几何泄漏，已经撤回。
5. 几何较干净的 v2.1 显示 AST 区域信息可解码，但当前简单 per-patch query 头只学到微弱且对随机种子敏感的定位信号，因此不进入官方测试或真实标注。

如果把整个仓库压缩成一个标题，可以是：

> **更精细的文本不会自动产生更好的声音表示：呼吸音 schema 对齐的系统负结果、撤回记录，以及 AST 表示的意外优势。**
