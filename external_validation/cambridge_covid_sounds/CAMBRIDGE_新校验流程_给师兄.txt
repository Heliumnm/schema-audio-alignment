三、提交CPU校验任务
------------------

cd /home/yl809/projects/covid/external_validation/cambridge_covid_sounds

sbatch submit_reconstructed_match_first_v2.slurm \
  /home/yl809/rds/hpc-work/datasets/covid19/metadata \
  /home/yl809/rds/hpc-work/datasets/covid19 \
  /home/yl809/projects/covid/external_validation/cambridge_covid_sounds/cambridge_audit_output_webfix_v2

该任务不申请GPU；默认2小时、2 CPU、16 GB。它会：

1. 用Android/iOS Uid和Web Folder Name重建稳定participant；
2. 按UID+submission folder精确连接metadata与cough；
3. 执行真实WAV解码、时长、finite/nonzero、raw hash与PCM hash检查；
4. 排除跨participant重复音频；
5. 从所有合格participant中先冻结100对matched target；
6. 只把剩余participant按label×platform划分70/15/15；
7. 生成不含任何ID和路径的Task-2 split/audio overlap report；
8. 重新打包public/PUBLIC_RESULTS.zip。

五、必须核对的结果
----------------

public/overlap_report.json应当报告：

1. Task-2 unique UID count = 1000；
2. Task-2 unique sample/submission count = 1486；
3. 每UID recording数量分布；
4. Android / iOS / Web UID = 300 / 682 / 18；
5. Task-1 ∩ Task-2 UID = 未测量（Task-1未下载）；
6. Task-1 ∩ Task-2 sample-ID = 未测量（Task-1未下载）；
7. train ∩ validation UID = 0；
8. train ∩ matched-target UID = 0；
9. validation ∩ matched-target UID = 0；
10. 跨split decoded PCM hash = 0，跨split raw-file hash = 0。

Task-1/Task-2重叠只作描述，本次明确记为未测量；不能写成0。第7--10项必须为0。

纵向标签还要报告：

- 同一稳定UID出现多个原始COVID状态的人数；
- 同时出现两种严格endpoint标签的人数；
- 因严格标签冲突而被排除的人数；
- 最终保留的严格标签冲突人数必须为0。

冻结规则是：positive仅为positiveLast14/last14；negative仅为negativeNever；其他状态先排除；
若同一稳定UID同时出现两种严格标签，整名participant排除；同标签多次submission用固定、
label-blind的UID+folder hash只选一次；选中submission内若有多条cough，分别编码后在participant
层面作算术平均；不额外推算检测日期窗口。

public/data_gate.json还必须满足：

- verdict = GO；
- identity_namespace_version = cambridge-task2-official-loader-v1；
- matched target = 100对；
- max absolute SMD <= 0.12；
- max fine-balance difference <= 0.08；
- 所有split与profile gate通过。
