CAMBRIDGE COVID-19 SOUNDS 数据门：SLURM运行指南
================================================

说明
----

这个阶段只重建患者队列并检查metadata、音频质量、数据划分和匹配可行性。
它不会加载AST、OPERA或Phi-2，也不会训练模型，因此不需要GPU。

请不要在集群登录节点直接长时间运行，应通过Slurm提交到CPU计算节点。


一、更新代码
------------

如果仓库已经下载：

cd schema-audio-alignment
git pull origin main
git rev-parse --short HEAD

如果还没有下载：

git clone https://github.com/Heliumnm/schema-audio-alignment.git
cd schema-audio-alignment


二、第一次运行时创建环境
----------------------

cd external_validation/cambridge_covid_sounds

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements-gate.txt


三、Slurm提交脚本
----------------

当前match-first v2使用：

submit_reconstructed_match_first_v2.slurm

默认资源为2个CPU、16 GB内存和8小时，不申请GPU，不需要修改仓库路径。
旧的submit_reconstructed_gate.slurm是已记录为NO_GO的split-first v1，仅用于历史复现。

如果集群要求指定partition或account，请在该文件开头按当地规定增加：

#SBATCH --partition=你的CPU分区
#SBATCH --account=你的项目账号


四、提交任务
------------

在external_validation/cambridge_covid_sounds目录运行：

sbatch submit_reconstructed_match_first_v2.slurm \
  /实际路径/covid19/metadata \
  /实际路径/test2 \
  /实际路径/cambridge_match_first_v2

三个参数依次是：

1. metadata目录，里面应有android.csv、ios.csv、web.csv；
2. 音频母目录，结构应为ID/采集时间/audio_file_cough.wav；
3. 输出目录。

第二个参数必须指向保持了ID/采集时间目录结构的Task-2音频子集；不需要下载完整200GB+母库。


五、查看任务状态和日志
--------------------

查看状态：

squeue -u "$USER"

查看标准输出：

tail -f cambridge_gate_任务编号.out

查看错误日志：

tail -f cambridge_gate_任务编号.err

任务结束后，可在日志末尾看到：

DATA GATE GO

或者：

DATA GATE NO_GO


六、返回结果
------------

只需要返回：

/实际路径/cambridge_match_first_v2/public/PUBLIC_RESULTS.zip

不要发送：

/实际路径/cambridge_match_first_v2/private/

private目录包含患者ID、音频路径和匹配关系，必须留在DTA授权环境内。

如果结果是NO_GO，请停止，不要修改match-first顺序、70/15/15开发划分、100对、0.12 SMD或0.08
fine-balance门槛，也不要启动任何模型。

如果结果是GO，请先把PUBLIC_RESULTS.zip发给项目负责人核对；收到明确解锁指令后，
再单独提交正式GPU实验。
